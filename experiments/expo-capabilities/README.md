# Expo 原生能力实验

> 状态：首轮实验已结束，工程冻结为技术参考
> 结论：React Native + Expo + TypeScript 与 Expo Router 确认为 MVP 客户端方案

该工程用于执行实施路线 `S0.2`–`S0.4`，验证 React Native + Expo 是否满足小虾食堂的关键原生能力。它不是正式 App 工程，不再继续承载新的业务功能。正式 App 将复用已验证的依赖版本、路由方法、Figma token、权限文案和交互经验，但会按照真实认证、数据层、组件边界和环境配置重新初始化。

## 首轮结论

已验证：

- Expo SDK 58、React Native 0.88、React 19.3 和 TypeScript 6 的最小工程可运行。
- Expo Router 可以承载餐桌、菜谱、采购、我们的四项底部导航及设置二级页面。
- 相册多选、相机、图片压缩和系统分享的代码路径可以完成集成与打包。
- Figma 12 个画面的核心导航、日期日历与设置交互可以在 React Native 中表达。
- iPhone 16 Pro / iOS 18.4 模拟器中的安全区、中文、浅色视觉和页面跳转通过。
- TypeScript、ESLint、Expo Doctor 20/20 通过。
- iOS 与 Android 生产 bundle 均可成功生成。

尚未验证：

- 目标 iPhone 的真实照片权限、相机方向、图片质量和目标分享应用。
- Android 真机或模拟器的运行态、安全区和中文视觉。
- Supabase 登录、存储、数据持久化和退出登录。
- 正式 App 的离线队列、性能和发布构建。

这些未验证项已经转入正式 App：Android 运行态归入 `S1.10`，真机相册、相机、压缩和分享归入 `S2.10`。

## 已覆盖能力

- 相册图片多选（最多 5 张）。
- 相机拍摄及权限拒绝处理。
- 图片缩放和 JPEG 压缩。
- 系统文件分享面板。
- Expo Router 四项底部导航。
- 安全区和中文换行；当前只按 Figma 浅色视觉稿验收，深色模式等待设计稿。

## 运行

先确保 Node 与 npm 来自同一个 NVM 版本：

```bash
nvm use
npm install
npm run typecheck
npm run ios
```

## 正式 App 真机验收参考

按界面上的 1–4 顺序执行，并记录：

1. 首次授权、拒绝授权以及从系统设置恢复授权是否正常。
2. 能否一次选择 2–5 张菜谱截图，预览方向是否正确。
3. 相机拍摄后能否返回 App，照片方向是否正确。
4. 压缩过程是否稳定，输出图是否清晰且尺寸合理。
5. 分享面板是否打开，微信等目标应用能否收到清晰图片。
6. 刘海、安全区、中文换行以及深色系统环境是否正常。

模拟器无法替代相机、真实照片权限和目标分享应用验证；这些项目将在正式 App 对应阶段完成，不再继续扩展本实验工程。
