# AI 菜谱导入评测集

该目录用于实施路线 `S0.6`。真实截图可能包含账号名、头像和生活信息，不提交到公开仓库；默认只提交匿名化后的标注 JSON 和汇总结果。

## 目录约定

```text
evaluation/ai-recipe-import/
├── samples.local/          # 本地真实截图，Git 忽略
│   └── sample-001/
│       ├── 01.jpg
│       └── 02.jpg
├── expected/               # 人工确认后的标准答案
│   └── sample-001.json
├── outputs.local/          # 各模型原始输出，Git 忽略
└── results/                # 去敏后的聚合分数与决策记录
```

复制 `sample.example.json` 为 `expected/sample-NNN.json`，再填写人工标准答案。截图文件名只使用样本编号，不使用作者昵称或菜名中的个人信息。

## 首批样本配额

建议先收集 30 组，最低不得少于 20 组：

- 8 组单张清晰图文菜谱。
- 8 组多张连续截图。
- 4 组长图、字幕或密集排版。
- 4 组模糊、裁切不完整或带水印。
- 3 组多图重复信息。
- 3 组多图内容冲突。

菜型至少覆盖家常菜、汤、凉菜、主食和烘焙；单位至少覆盖克、毫升、个、把、勺、碗、适量和少许。一个样本可以同时计入多个类别。

## 评测流程

1. 人工阅读原图并建立 `expected` 标注，不参考候选模型输出。
2. 所有候选使用相同截图、输出 schema 和重试规则；温度固定为模型支持的最低稳定值。
3. 每个样本每个模型只运行一次主测试；API/网络失败可重试一次并单独记录。
4. 保存原始响应、结构校验结果、延迟、输入/输出 token 或图像计费单位和实际费用。
5. 自动计算字段指标，人工计时完成确认所需秒数。
6. 输出总体分数，也按清晰、多图、缺失、冲突和模糊单位分组查看，不能只看平均值。

## 指标定义

- 菜名准确率：标准化后完全正确的样本占比。
- 食材召回率：正确提取的标准食材数 / 标注食材总数。
- 食材错误新增率：无截图依据的食材数 / 模型输出食材总数。
- 数量与单位准确率：有明确标注的食材中，原始数量文本和单位均正确的比例。
- 步骤覆盖率：被正确提取的关键步骤数 / 标注关键步骤总数。
- 步骤顺序正确率：已提取关键步骤的相对顺序正确比例。
- 不确定项召回率：应标记为不确定的字段中被正确标记的比例。
- 结构成功率：无需修复即可通过 JSON Schema 的响应比例。
- 人工确认时间：从打开结果到确认可保存的秒数，中位数和 P90。
- 成本：单次和每 100 次导入的人民币估算，注明汇率日期。
- 延迟：端到端中位数和 P90。

## MVP 选择门槛

候选模型必须全部满足：

- 结构成功率 ≥ 98%。
- 菜名准确率 ≥ 95%。
- 食材召回率 ≥ 90%。
- 食材错误新增率 ≤ 3%。
- 不确定项召回率 ≥ 85%。
- 人工确认时间中位数 ≤ 90 秒。
- 每 100 次导入成本可被内部预算接受，并可通过限流设置上限。

达不到门槛时优先缩小自动化承诺、改进截图引导和确认体验，而不是让模型猜测缺失信息。

## 隐私要求

- 原始截图不上传到未经确认的第三方服务。
- 评测前遮盖与菜谱无关的头像、账号、私信、定位和订单信息。
- 记录候选服务的数据保留与训练政策。
- 模型密钥只从环境变量读取，不写入样本、输出或 Git。
